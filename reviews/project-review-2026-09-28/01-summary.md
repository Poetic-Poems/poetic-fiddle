# Summary

## What this project is

Poetic Fiddle is a Next.js 16 / React 19 / TypeScript web application: a `.poem` editor with a real-time HTML preview, Supabase-backed accounts, and database-backed save/share (permalinks), built for non-technical poets. It consumes the `poetic` framework's browser-safe `.poem` renderer as a tag-pinned release-tarball dependency rather than forking it. The codebase is ~13.7k lines across 112 files under `src/`, with 59 test files (Vitest + Testing Library, Playwright + axe-core for accessibility, pgTAP for the Supabase data layer).

The project is single-maintainer (Warwick Allen, documented as self-review-by-design in AGENTS.md's own Governance section) and worked concurrently by an autonomous multi-agent pipeline alongside the maintainer. It is past its MVP: every milestone in `docs/IMPLEMENTATION-PLAN.md` (M0 through the M8/M9 hardening items) is marked done, and three prior full project reviews (2026-07-23, 2026-07-31, 2026-08-08) have all found it in good health, with each successive pass confirming prior findings resolved.

## Overall assessment

Poetic Fiddle remains in good health at this revision. No Critical or High-severity finding surfaced across any of the 13 dimensions — the security posture in particular (authentication, authorization, RLS, CSP, sanitisation, secrets handling) is unusually rigorous for a project this size, and the codebase itself shows strong type discipline, disciplined error handling, and no dead code or `any`-escape-hatches. Automated checks corroborate this: 584/584 tests pass with 90.46% statement coverage, lint/typecheck/format are all clean, and the production build succeeds.

The headline story this pass is not a code defect but an operational one: production has run with no live Supabase backend since 2026-09-19 — sign-in, save and share are down for real users right now, a deliberate cost-driven decision the app degrades gracefully around, but with no visible plan or timeline for restoration, and with two of the project's own docs (`README.md`, `docs/REQUIREMENTS.md`) not fully updated to reflect it. Layered onto that is a second, related pattern: the project's autonomous pipeline has correctly detected and escalated two small, fully-specified, owner-only GitHub actions (closing a stuck empty draft PR, adding a check to branch protection) that have then sat unresolved for 6 and 4 days respectively — a live illustration of the bus-factor risk the project's own governance docs already name candidly. Separately, all three of the project's currently-open Dependabot PRs are CI-red because Dependabot isn't configured to bump version-locked package pairs together — a small, mechanical gap with an outsized effect on keeping dependencies current.

## Headline strengths

- Security fundamentals are excellent: bearer-token-verified auth on every sensitive route, default-deny RLS scoped correctly on every table, `search_path`-hardened `security definer` functions, timing-safe secret comparison, and a nonce-based CSP with a real-browser review checklist to catch what string-level tests can't [F-SEC-01 is the only SEC finding, and it's Low/informational].
- Type discipline and error handling are disciplined throughout: `strict: true` TypeScript with zero `any`-escape-hatches anywhere in `src/`, and every catch block either rethrows a typed domain error or is a deliberately-commented no-op [F-CODE-01, F-CODE-02].
- Data handling is clean: genuine database-enforced cascade deletion, an accurate personal-data inventory matching the code, and no personal data found in fixtures or test data [DATA dimension: no findings].
- Test coverage is strong and targeted at the riskiest paths (auth, account deletion/export), not just high on paper: 90.46% statement coverage with 584/584 tests passing, independently reproduced [F-TEST-01 through F-TEST-04 are all Low/Medium coverage-gap polish, not gaps in risk-weighted areas].
- CI/CD engineering is more sophisticated than typical for this project's size: a self-checking workflow-wiring guard, a weekly required-checks drift detector, and documented tribal knowledge in CONTRIBUTING.md about specific past false-positive/false-negative CI failure modes.

## Headline risks

- Production has had no live backend and no visible restoration plan for 9 days, and two of the project's own docs haven't caught up with that fact [F-GOV-03, F-OPS-01, F-DOC-01].
- All three open Dependabot PRs have been CI-red for over a week because version-locked package pairs (`react`/`react-dom`, `vitest`/`@vitest/coverage-v8`) aren't grouped in Dependabot's config [F-DEPS-01].
- A stuck, empty draft recovery PR has sat unresolved for 8 days despite two correct pipeline escalations, because closing it requires owner-only GitHub permissions [F-GOV-01] — the same structural gap as a second, smaller stuck item (a required-check ruleset edit) [F-GOV-02].
- A previously-shipped mobile bug's regression fix (postscript clamping on pane-visibility change) has no test proving it still fires [F-TEST-03].
- Two internal docs disagree with each other about the same fact (`README.md`'s CI section vs. its own "Environment & secrets" section; `docs/REQUIREMENTS.md` vs. `docs/IMPLEMENTATION-PLAN.md` on the Supabase plan) [F-DOC-01, F-GOV-03].

## Scope and method

**Sampling:** Given the codebase's moderate size (~13.7k LOC) and the prior review's established good health with no Critical/High carryover, this pass read close to exhaustively in security-sensitive and core-logic areas (auth routes, RLS-dependent Supabase access, the sanitisation/rendering boundary, account export/delete, share/remix routes, the CI/CD workflow set, and every top-level doc) and sampled representatively elsewhere (a cross-section of components, hooks, and tests, chosen to cover the largest/highest-fan-out files first). Work was parallelised across three subagents by dimension group (ARCH+CODE; SEC+DATA+OPS; TEST+PERF+UX+DOC), with DEPS, CI, TOOL and GOV reviewed directly by the lead reviewer, who also investigated the repository's live GitHub state (open PRs, open issues, workflow run logs) as primary evidence rather than relying on the repo's own docs alone.

**Automated tools run:** `npm audit` (0 vulnerabilities, both prod-only and full), the project's own `npm run audit` canary check, `npm run lint` (1 pre-existing warning, unrelated to this review), `npm run typecheck` (clean), `npm run format:check` (clean, aside from this review's own output), `npm run coverage` (584/584 tests, 90.46%/85.05%/90.61%/92.19% statement/branch/function/line — run twice independently, by the lead reviewer and again by the TEST-dimension subagent, with identical results), `npm run build` (succeeds), `npm outdated`, `madge --circular` (0 circular dependencies), and live inspection of GitHub Actions run logs, PR check-run results, and issue history via `gh`.

**Tools that could not run, and why:** `npm run test:a11y` (Playwright + axe-core) could not run — the review sandbox has no root for `playwright install --with-deps` and its egress proxy blocks the Playwright CDN for a plain browser download. `npm run test:db` (Supabase pgTAP) could not run — the Supabase CLI needs a Docker daemon, unavailable in this sandbox. Both were assessed by inspection instead (CI wiring for the former; migration and pgTAP source files for the latter) and are recorded as scope limitations, not findings. Separately, this review's environment provided Node.js v26.8.2 against the repository's pinned `22.x`, with no alternate-version tooling available; dependencies were installed with `--engine-strict=false` as a one-time override so the automated checks above could run at all — recorded as F-TOOL-01, a caveat on this review's own results rather than a repository defect.

**Dimensions judged inapplicable:** none — all 13 dimensions from the checklist were reviewed; PERF and DATA returned no findings, which is recorded plainly in `02-findings.md` rather than omitted.

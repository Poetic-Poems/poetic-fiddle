*Filed 2026-08-01, while resolving TD-PPpfid-26072435.* The `jest-axe`
smoke tests added in that item (`src/components/Editor.a11y.test.tsx`,
`src/components/PoemsDashboard.a11y.test.tsx`) run under Vitest's `jsdom`
environment, which has no real layout or rendering engine — axe-core's
`color-contrast` rule silently doesn't run at all under `jsdom` (confirmed:
it appears in none of a run's `passes`/`violations`/`incomplete`/
`inapplicable` results), so the suite cannot catch contrast regressions
like the one TD-PPpfid-26072416 fixed by hand.

Fix: run `axe-core` against the built app in a real browser context (e.g.
Playwright + `@axe-core/playwright`, or `pa11y-ci` against a local `next
build && next start`) so contrast checks actually execute; wire it into
CI alongside (not replacing) the existing `jsdom`-based smoke tests, which
remain useful for the checks that don't need real rendering (labels, roles,
alt text, aria attributes).

Referenced in a code comment in `Editor.a11y.test.tsx` and
`PoemsDashboard.a11y.test.tsx` — remove those references when resolving.

*Filed 2026-08-04, from the review of PR #202 (TD-PPpfid-26080108):
https://github.com/Poetic-Poems/poetic-fiddle/pull/202#pullrequestreview-4849689796.*

`TD-PPpfid-26080108` wired `evaluatePostscriptPreviews` (measurement) and a
debounced `resize` listener into both preview views so a rendered postscript
clamps in agreement with a published Poetic page (AC2). It holds for
`SharedPoemView`, but not for the editor's mobile preview pane.

`Editor.tsx:366-374` keeps `PoemPreview`'s iframe permanently mounted below
`lg` and switches panes with `hidden` (`display: none`), toggled by the
source/preview switch at `mobileView` (`Editor.tsx:59`). Consequences on a
narrow viewport:

- The iframe still loads while `display: none`, so `PoemPreview.tsx`'s
  `handleLoad` (`:186-191`) measures a zero-size box —
  `evaluatePostscriptPreviews` (`:132`) sees `hiddenPx` come out negative, so
  it never adds `.postscript-clamped`.
- Switching `mobileView` to `"preview"` only changes a class; it fires neither
  `load` nor `resize` on the iframe, so nothing re-measures at the moment the
  pane actually becomes visible.
- The next re-measure only happens on the next keystroke, which reloads the
  `srcDoc` and re-fires `load` — but that happens while typing, i.e. while the
  source pane (not the preview pane) is the one showing, so it measures zero
  again.

Net: on mobile, every postscript in the editor preview renders fully
expanded, with no "See more" control. `evaluatePostscriptPreviews` is
designed so that's a graceful degradation — readable content, no dead
control, per `TD-PPpfid-26080108`'s AC — so nothing is broken. But it is a
behaviour change from the previous always-on CSS clamp, and it means the
editor preview disagrees with a published Poetic page at the same viewport
width, which is what AC2 asks for.

Fix (proposed by the PR #202 review, not yet decided): a `ResizeObserver` on
the iframe element in `PoemPreview.tsx`. Unlike the window `resize` listener
it fires on the 0-size → sized transition, so it covers both the pane-toggle
case and the window-resize case that `poetic.js`'s listener addresses —
letting it subsume, rather than sit alongside, the existing `resize`
listener added in `TD-PPpfid-26080108`. `PoemPreview.tsx`'s `useEffect`
(`:193-206`) is where the `resize` listener currently lives and where a
`ResizeObserver` would replace it.

Where: `src/components/Editor.tsx` (`mobileView`, the mobile preview pane),
`src/components/PoemPreview.tsx` (`handleLoad`, the `resize` `useEffect`).

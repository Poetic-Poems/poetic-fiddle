*Filed 2026-08-09, from the 2026-08-08 project review (R-12, F-CI-02).*
Severity: Low. `npm run audit` (`npm audit --audit-level=high`) has no
retry/backoff, and the advisory database it queries moves independently of
this repo's tree — of the last 19 `CI` runs on `main`, 2 failed solely on
the `Audit dependencies` step, and the *identical* commit `a6647036` failed
audit at 2026-08-07T23:13 and passed at 03:53 the same night logging
"found 0 vulnerabilities." This is not hypothetical: it is the documented
proximate cause of a real process incident (PR #221's Reviewer legitimately
couldn't merge a red required check; by the time it turned green the
branch had been closed as void and later re-swept as orphaned, producing
draft PR #223 and escalation issues #224/#228 — see GOV findings in
`reviews/project-review-2026-08-08/02-findings.md`). `dependency-audit.yml`'s
weekly cousin shares the same failure mode.

Fix (optional, proportionate to project scale): a short retry-with-delay
(e.g. two attempts a few minutes apart) before failing the `audit` job, or
a documented norm that a red audit-only CI run on an otherwise-clean PR
gets re-run once before concluding the branch needs rework. See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-12.

Correction (2026-08-17, issue #337): the direction of the flake recorded
above is inverted. The 23:13 run on a6647036 correctly reported two live
advisories (GHSA-2v37-7h3g-55p8, nanoid, HIGH; GHSA-55q2-fjhq-7xh7,
dompurify, MODERATE, neither withdrawn); the 03:53 run returned an empty
advisory set for the same unchanged tree. The fix this item suggests — a
retry before failing — moves in the wrong direction against a flake whose
signature is a spurious green. See #336 for the defect and #337 for this
correction.

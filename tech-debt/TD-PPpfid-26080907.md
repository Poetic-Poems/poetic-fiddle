*Filed 2026-08-09, from the 2026-08-08 project review (R-08, F-TOOL-01).*
Severity: Low. `scripts/` has five `.mjs` utility scripts with real logic,
and every one except `sync-poetic-css.mjs` has a matching `*.test.mjs`
(`check-changelog-rename.test.mjs`, `check-supabase-auth-drift.test.mjs`,
`check-workflow-wiring.test.mjs`, `export-poet-data.test.mjs`,
`extract-changelog-notes.test.mjs`). `sync-poetic-css.mjs` has a real
branching path worth testing — the `require.resolve` failure case that
throws the actionable error message its header comment describes — with
no test covering it. Vitest's default include glob already picks up
`*.test.mjs` anywhere in the tree, so adding one needs no config change.
This is the one script that runs unconditionally on every `npm install`
(via `postinstall`) and is explicitly designed to guard against a specific
upstream-drift scenario (`poetic`'s CSS export path moving) — its own
correctness is currently unverified by any test, breaking the project's
otherwise-consistent "every script gets a test" convention.

Fix: add `scripts/sync-poetic-css.test.mjs` covering at least the
`require.resolve` failure path (mock/stub resolution to throw and assert
the wrapped error's message). See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-08.

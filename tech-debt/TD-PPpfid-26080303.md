`docs/PRIVACY-EXPORT-DELETE-RUNBOOK.md`'s "Backup / PITR coverage" section
states Supabase's *published* Pro-plan defaults (daily backups, 7 days'
retention; Point-in-Time Recovery as a separate paid add-on) and says
explicitly that whether the PITR add-on is enabled for the "Poetic Fiddle"
project itself is not confirmed — the agent that wrote it had no Supabase
dashboard access. `README.md`'s "Backups" section inherits the same
limitation.

So the recovery point actually available to this project is currently
assumed, not known: the runbook tells a reader to assume the Pro default of
up to ~24 hours of data loss on restore, which is the safe direction but may
understate what is really there.

Fix: someone with Supabase dashboard access checks **Project Settings →
Database → Backups** for the "Poetic Fiddle" project, then updates the
runbook's "Backup / PITR coverage" section with the confirmed status
(including the actual retention/recovery window) and removes the
"not confirmed by this document" caveat paragraph. Update `README.md`'s
"Backups" section to match if the confirmed position differs from the
published default.

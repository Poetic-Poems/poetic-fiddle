`playwright.config.ts` sets `retries: 1` under CI, so an a11y check that
fails once and passes on retry produces a green `a11y-contrast` job — a
sensible trade for a required check, since the suite's content is
deterministic (static signed-out pages, fixed colour schemes) and retries
exist to absorb infrastructure flake. But the job's "Upload Playwright
report" step (`.github/workflows/ci.yml`) runs only `if: failure()`, so on
a flaky-then-green run everything the report captured is discarded with
the runner: the first attempt's failure output (including the axe
violations JSON the `expect(results.violations).toEqual([])` diff prints)
and the retry's trace (`trace: "on-first-retry"` records the retry
attempt). Playwright does mark the test "flaky" in the log, but nobody
reads the logs of a green job — an intermittent contrast failure would be
retried into a pass invisibly, with nothing left to diagnose.

Fix: change the upload step's condition from `if: failure()` to
`if: always()` so the report is preserved on every run (on a fully green
run it is small — no traces are recorded without a retry — and
`retention-days: 7` keeps the cost trivial). Optionally rename the
artifact per run attempt if re-runs ever collide. Then confirm on a
flaky-then-green run that the uploaded report contains the first attempt's
failure details and the retry's trace.

Noticed in the reviewer pass on PR #194 (the `retries: 1` note); filed as
a follow-up after Warwick's review of those judgement calls.

*Filed 2026-08-09, from the 2026-08-08 project review (R-07, F-SEC-01).*
Severity: Low. `scripts/check-supabase-auth-drift.mjs`'s `ALLOWLIST`
(lines 85-169) checks password/complexity, signup/anonymous toggles, JWT
expiry, refresh-token rotation, email OTP, and every MFA field, but has no
entry for `supabase/config.toml`'s `[auth.rate_limit]` section
(`sign_in_sign_ups`, `token_verifications`, `email_sent`, etc.,
`supabase/config.toml:176-188`) or `[auth.captcha]` (currently disabled,
`:191-194`). `.github/workflows/supabase-auth-drift.yml` (daily) faithfully
checks everything the allowlist names and files a deduplicated issue on
disagreement — but a live rate-limit or CAPTCHA setting that drifts from
(or was never set to match) the committed file would produce no red run
and no issue, unlike every other allowlisted auth control. No evidence the
live values actually disagree with `config.toml`'s defaults today — this
is a monitoring gap, not a confirmed live misconfiguration.

Fix: extend `ALLOWLIST` with the `[auth.rate_limit]` fields, each
individually verified against its Management API counterpart per the
file's own stated methodology; if CAPTCHA is a deliberate "not yet" rather
than an oversight, record that decision in `docs/REQUIREMENTS.md`/
`docs/IMPLEMENTATION-PLAN.md`. See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-07.

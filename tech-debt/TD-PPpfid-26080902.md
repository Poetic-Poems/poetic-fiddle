*Filed 2026-08-09, from the 2026-08-08 project review (R-02, F-TEST-01,
F-TEST-02, F-TEST-03).* Severity: Medium. Two gaps, found via
`npm run coverage`:

1. `src/lib/render-share.ts`'s `renderSharedPoemHtml` (the try/catch that
   turns a saved-but-unparseable `.poem` source into the public share
   page's friendly-degrade instead of a 500) is never called by any test —
   `render-share.test.ts` only exercises the inner `sanitizeSharedPoemHtml`,
   and `share/[share_id]/page.test.tsx` fully mocks the wrapper. Coverage:
   78.37%/73.33%/66.66%/82.85% stmt/branch/func/line, with the catch body
   (lines 110-117) and the malformed-embed-URL catch (line 65) both
   uncovered. The client-side equivalent (`tryRenderPoem` in
   `use-poem-persistence.ts`) *is* tested against a real parse failure —
   this is an asymmetry between the two renderer call sites.
2. `src/lib/supabase-server.ts` — `getSupabaseAdmin()`/`getSupabaseServer()`
   — is at 0% coverage across every metric; both real consumers
   (`route.test.ts`, `shared-poem-cache.test.ts`) mock the module entirely.
   `getSupabaseAdmin()` is, by its own doc comment, "the only place [in the
   codebase] that can bypass RLS," backing the account-deletion route. The
   fail-closed guard (throw if `SUPABASE_SERVICE_ROLE_KEY` is unset) is
   currently asserted only by reading the code.

A third, smaller gap in the same area: `src/components/Editor.share.test.tsx`
is the one remaining fake-timer test file without the
`afterEach(() => vi.useRealTimers())` safety net that
`use-poem-persistence.test.ts`/`PoemPreview.test.tsx`/`SharedPoemView.test.tsx`
already have (added for the 2026-07-31 review's F-TEST-02) — a failing
`expect()` between its `vi.useFakeTimers()` and manual
`vi.useRealTimers()` would leak fake timers into the next test in the file.

Fix: add a case to `render-share.test.ts` calling `renderSharedPoemHtml`
(not `sanitizeSharedPoemHtml`) with genuinely unparseable source, asserting
`{ html: "", error: true }` and that `reportSwallowedError` fires; add a
small unmocked test for `supabase-server.ts` asserting both getters throw
when their env var is unset and construct when set; add the same
`afterEach` to `Editor.share.test.tsx`. See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-02.

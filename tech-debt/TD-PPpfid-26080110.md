*Filed 2026-08-01, from the reviewer notes on the pull request resolving
TD-PPpfid-26080107 ([#176](https://github.com/Poetic-Poems/poetic-fiddle/pull/176)).*
Severity: Low. The `npm audit --omit=dev --audit-level=high` step that
TD-PPpfid-26080107 added to `.github/workflows/ci.yml`'s `build` job is
narrower than "npm audit in CI" sounds, in two ways:

1. `--omit=dev` was chosen to exempt one known, tracked advisory chain
   (`eslint` → `minimatch` → `brace-expansion`, GHSA-mh99-v99m-4gvg,
   TD-PPpfid-26072429), but it exempts the *entire* devDependencies tree
   permanently — a future high-severity advisory anywhere in the build
   toolchain (the code that runs in CI and on maintainer machines) would
   never fail this gate.
2. The `build` job is conditional on the diff classifier
   (`if: needs.changes.outputs.app == 'true'`), so a prose-only pull
   request runs no audit at all, and an advisory published while no
   app-classified PRs are landing goes unnoticed by CI.

Dependabot still covers devDependencies out-of-band, so this is a
narrower-than-it-sounds gate rather than a hole — hence Low.

Fix: when TD-PPpfid-26072429's eslint chain is resolved upstream, narrow
the exemption — either drop `--omit=dev` so the full tree is audited, or
replace it with an `audit-ci` allowlist that names the specific advisories
being tolerated (each with a reference to its register item) and fails
closed on everything else. Optionally, add a scheduled (cron) audit run on
`main` so newly published advisories are caught even when no app-classified
PRs are landing. The comment above the audit step in `ci.yml` explains the
current exemption — update it when narrowing.

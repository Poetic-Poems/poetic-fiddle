*Filed 2026-08-09, from the 2026-08-08 project review (R-03, F-CI-01).*
Severity: Medium. `package.json`'s `version` is still `"0.1.0"`, and
`gh api repos/Poetic-Poems/poetic-fiddle/releases` returns exactly one
release (`v0.1.0`, published 2026-07-12), predating the MVP (M7,
2026-07-18) and almost everything now in production. `CHANGELOG.md`'s
`## [Unreleased]` section is 400 of the file's 410 lines and has never been
renamed since M7 shipped, meaning `docs/RELEASE-RUNBOOK.md`'s documented
procedure (bump version, rename the CHANGELOG heading — enforced by the
`changelog-rename` CI gate — `release.yml` tags and publishes on push) has
apparently never been exercised past the initial scaffold. `main` deploys
continuously to Vercel independent of `release.yml`; no `vercel.json` or
rollback runbook exists in the repository, and a grep for "rollback"
across `docs/*.md`/`README.md` finds nothing. The mechanism itself is well
engineered (`release.yml`'s header comment reasons carefully about ordering
and re-run safety) — this is a usage gap, not a design gap — but if a bad
deploy needed a documented rollback target, the only repo-recorded
checkpoint predates nearly every shipped feature.

Fix: either cut a release (e.g. tagging the current state, or whatever
cadence suits a solo maintainer) so the tag history means something going
forward, or explicitly document in `docs/RELEASE-RUNBOOK.md`/`README.md`
that Fiddle doesn't use tags as its deployment/rollback mechanism and name
what does (Vercel's deployment-history/rollback UI). See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-03.

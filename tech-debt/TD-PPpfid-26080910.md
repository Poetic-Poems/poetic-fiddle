*Filed 2026-08-09, from the 2026-08-08 project review (R-11, F-ARCH-01,
F-DOC-02).* Severity: Low. Two small, unrelated documentation drifts found
this pass:

1. `docs/IMPLEMENTATION-PLAN.md`'s M8/M9 W-item list (§4) has gone stale on
   two items it explicitly commits to keeping current: **W10**
   ("Breach-handling statement... Nothing user-facing today") is now done —
   `src/app/privacy/page.tsx:169-179` has a "Privacy breach notification"
   section since PR #180 (2026-08-01). **W14** ("Data export... No export
   flow exists") is now partially addressed — `scripts/export-poet-data.mjs`
   plus `docs/PRIVACY-EXPORT-DELETE-RUNBOOK.md` shipped in PR #191
   (2026-08-04), though it's a maintainer-run admin script, not the
   self-service flow the item originally described, so W14 needs a status
   nuance, not just a "done" flip.

   account-deletion route as "reachable from the app's account settings" —
   no settings route exists; the feature is the "Danger zone" section of
   the "My poems" dashboard (`src/app/poems/page.tsx`), which the same
   document correctly calls "Danger zone" two paragraphs later.

Fix: update W10 to "done (PR #180)"; update W14 to describe the admin-run
export mechanism and narrow its remaining scope or close it with a pointer
to the runbook; change "the app's account settings" to "the My poems
dashboard's Danger zone" in the runbook. See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-11.

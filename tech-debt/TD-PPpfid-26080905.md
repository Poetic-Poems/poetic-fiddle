*Filed 2026-08-09, from the 2026-08-08 project review (R-06, F-UX-01).*
Severity: Low. `src/components/PoemsDashboard.a11y.test.tsx` renders
`PoemsDashboard` signed-out and with a loaded poem list, but never opens
the per-row delete confirmation (`PoemsDashboard.tsx:294-322`) before
running `axe()`. The same file also mounts `AccountDangerZone`, but its
confirmation `<dialog>` content (`AccountDangerZone.tsx:113-172`) is only
in the DOM once `open` is `true`, which the test never triggers either.
Both surfaces were reviewed and fixed for keyboard/focus behaviour
elsewhere (`PoemsDashboard.test.tsx`'s "delete focus management" describe
block; `AccountDangerZone.tsx`'s native-`<dialog>` handling) — this is a
gap in the automated accessibility regression net specifically, not a
known live defect. A future regression to either open-state's markup
(an added unlabelled icon button, a lost `role`) would ship past `npm test`
undetected, on the app's two most destructive actions.

Fix: add an `axe()` assertion after opening each confirmation (a
`fireEvent.click` on "Delete" / "Delete account" before calling `axe()`),
mirroring the existing focus-management tests' setup. See
`reviews/project-review-2026-08-08/04-improvement-prompts.md` R-06.
